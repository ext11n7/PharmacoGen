# Текст выступления: PharmacoGen

Здравствуйте! Я представляю PharmacoGen — веб-приложение для исследовательского изучения связи лекарственных препаратов и генов. Его задача — помочь собрать сведения из разных открытых источников, организовать их и подготовить материалы для дальнейшей проверки.

Для демонстрации я использую варфарин и ген CYP2C9. Пользователь может выбрать препарат и ген в форме, а при необходимости указать вариант, например rs1799853. Приложение получает данные из источников и показывает досье со ссылками и ограничениями. Подсказки помогают найти названия препаратов и генов без необходимости помнить их наизусть.

**Показать:** выбрать warfarin и CYP2C9, запустить исследование и открыть результаты.

В основе первого задания — разделение исследования на задачи агентов. Координатор готовит запрос; агенты источников получают данные FAERS и ClinVar; далее приложение собирает результаты и показывает исследовательское досье. В интерфейсе видны этапы и доступность источников. Это организованная последовательность программных компонентов: я не утверждаю, что каждый агент является отдельной языковой моделью.

FAERS содержит сообщения о нежелательных явлениях, связанных с лекарствами. Здесь мы ищем сообщения по препарату. Такое сообщение не доказывает причинность, а число сообщений не является частотой реакции. Запрос FAERS не содержит генотип и сам по себе не доказывает связь с геном.

ClinVar содержит записи о генетических вариантах и их интерпретации. Важно смотреть не только на классификацию, но и на признак, к которому она относится, и на статус проверки. Классификация варианта в ClinVar не означает автоматически влияние на ответ на препарат.

Для продолжения исследования приложение ищет статьи в PubMed и получает доступные аннотации через Europe PMC. Также отображаются метаданные рекомендаций CPIC и аннотации ClinPGx по паре препарат–ген. Совпадение пары ещё не означает, что каждая аннотация относится к введённому варианту. Ссылки позволяют самостоятельно открыть исходные материалы.

Во втором задании я использую MCP — Model Context Protocol. Агент или приложение остаётся организатором исследования, а MCP предоставляет стандартный способ вызвать инструмент и получить ответ. Это разные роли: MCP — не отдельный исследователь и не доказательство правильности вывода.

В публичной версии клиент и сервер MCP работают внутри серверной функции Netlify и обмениваются сообщениями через внутренний транспорт официального SDK. Локальные подключения убраны из пользовательского интерфейса, потому что посетителю опубликованного сайта они недоступны. В журнале можно увидеть фактические сообщения инициализации, получения каталога и вызова инструмента.

Чтобы показать пользу MCP, после исследования я могу выполнить несколько разных действий. Например, найти фразу «bleeding» внутри собранных материалов: инструмент проверит заголовки, доступные аннотации и описания записей, затем вернёт фрагменты с прямыми ссылками. Это буквальный поиск без перевода, поэтому для англоязычных текстов я использую английское слово.

Другое действие — выбрать две записи из списков и сопоставить их содержание: например, две статьи или запись ClinVar и аннотацию ClinPGx. Сервис показывает их исходные сведения и ограничения. Он не объявляет автоматически, что записи согласуются или доказывают эффект. Также доступны проверка полноты, сопоставление обозначения варианта, план дальнейшей проверки, разбор типов публикаций и просмотр классификаций ClinVar. Досье подставляется автоматически, повторно вводить препарат и ген не требуется.

**Показать:** завершить исследование, перейти в MCP, найти «warfarin» в материалах, затем выбрать две разные записи и выполнить сравнение. Открыть первоисточник по ссылке.

Основное исследование собирает данные через серверные функции, а действия на странице MCP выполняются через MCP-клиент и сервер. Для сбоя получения аннотаций предусмотрен резервный путь: если Europe PMC не отвечает, приложение обращается к PubMed через efetch. Если получить аннотации всё же невозможно, модель не должна придумывать содержание отсутствующих материалов.

В приложении также используется языковая модель. В опубликованной версии запрос идёт к модели Qwen через API Groq; локально может использоваться Qwen через Ollama. Модели передаются ограниченные сведения из найденных источников, и она составляет обзор со ссылками на переданные идентификаторы. Проверка идентификатора не доказывает корректность интерпретации: каждое утверждение необходимо сверять с публикацией. Полные тексты статей автоматически не анализируются.

**Технологический стек и основа реализации.** Интерфейс написан на HTML, CSS и JavaScript; у него есть русская и английская локализация и светлая и тёмная темы. Локальная серверная часть написана на Python: она запускает веб-сервер, компоненты исследования и MCP-серверы через Python SDK. Запросы к медицинским источникам используют их открытые API. Для публичной версии используются JavaScript-функции Netlify и официальный JavaScript SDK MCP; сайт размещён на Netlify, исходный код хранится в GitHub. Groq предоставляет API модели, а Ollama запускает модель локально. У проекта нет собственной обученной медицинской модели или собственной медицинской базы — он работает поверх перечисленных сервисов.

Таким образом, PharmacoGen объединяет поиск, проверку и представление исследовательских материалов. Главная ценность — возможность перейти от вопроса о препарате и гене к структурированным источникам и дальнейшим шагам. Приложение предназначено для исследования, не подбирает индивидуальную дозировку и не заменяет медицинское решение. Спасибо за внимание!
